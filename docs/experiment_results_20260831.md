# MitoEvidence-Hy3 真实实验结果与适用边界

> 快照日期：2026-08-31
> 参考标准：项目负责人指定的 127 条单一专家共识记录
> 模型：腾讯云 TokenHub `hy3`（凭据仅从环境变量读取）

机器可读聚合结果见 [`results/experiment_summary_20260831.json`](results/experiment_summary_20260831.json)。

## 1. 先说明“专家一致性”

现有数据对每个条目只有一份合并后的专家共识结果，没有专家 A、专家 B 的独立逐项标签。
因此本项目**不能计算专家间** Cohen's κ、Gwet's AC1/AC2 或 ICC。下文所有 κ、准确率和
混淆矩阵均表示**自动系统相对单份专家共识参考**的一致度，不能改写为专家间可靠性。

127 条记录由四种不同任务组成，不能混成一个总准确率：5 道 Pilot 问题、50 条 Claim
准入审核、60 组术语/条件错误正误对和 12 篇综述池评估。

### 2.1 术语/条件错误判别

- 173/180 次选择专家参考中的正确表述，0 次选择错误攻击表述，7 次 abstain；
- 60 个条目中 58 个的三次多数票正确；Wilson 95% CI 为 88.64%–99.08%；
- 60 个条目全部至少有两次成功重复，重复两两一致率为 96.67%，一致三次的条目占 95%；
- 数据存在明显长度偏差：正确表述在 54/60 对中更长，“只选更长句”基线已经达到 90%；
- Hy3 与长度基线的条目级精确双侧 McNemar 检验为 `p=0.21875`，当前样本不能证明 Hy3
  显著优于这一简单偏差基线。

所以，这组结果能证明评估流程有判别力并能观测采样稳定性，但还不是方案中完整的
“好—中—差”三档验证，也不是 12 类全文对抗攻击的完整检出率。

### 2.2 Claim 准入

专家参考分布为 accept 8、accept_with_edits 25、reject 14、uncertain 3；Hy3 分布为
accept 25、accept_with_edits 19、reject 4、uncertain 2。系统明显偏向保留：

- reject 召回率仅 1/14（7.14%），uncertain 召回率为 0/3；
- 若仅把 accept/accept_with_edits 合并为“保留候选”，召回率为 90.91%、精确率 68.18%；
- 同一二分类视角的特异度只有 17.65%，说明它会放过大量应阻断或不确定的候选。

因此当前 Hy3 Claim 模块最多可作为**高召回候选生成器**，不得替代严格规则或专家准入。
四分类准确率低于多数类基线，是需要公开呈现的失败结果，而不是从报告中删除的异常值。

### 2.3 正式 A/B/C/D v4

正式套件 `pilot-abcd-hy3-v4-formal-r1-20260831` 运行于合入后的主分支
`05adb6a1cefb5bcd14a93832f34e4f891a2037c7`。固定配置为 5 题、3 次生成重复、top-k=12，
D 对每条 C 主张进行 7 次 Hy3 Judge 采样。总耗时 13,227 秒（3 小时 40 分 27 秒），
60/60 cell 成功、失败 0；独立文件与跨臂审计为 `production_ready=true`、0 error。

v4 产生前保留了一次未完成的 v3 诊断套件：前 8 个 cell 全部失败，其中 6 个 A/B/C
并非 HTTP 或内容评分失败，而是生成已在第 2—4 次有界结构修复后成功、随后被 v3 的
`attempt_count==1` 规则拒绝；2 个 D 因 C 不可用而级联失败。该套件在任何结论分析前被中止，
没有 summary，也不计入 v4 指标。v4 未追认或覆盖它，而是以新 Schema 明确把部署系统已有的
有界结构修复纳入方法，并同时报告一次通过率。

McNemar p 值分别为 0.50、1.00、0.125。D 的点估计和重复稳定性最高，但样本量不足，不能宣称
相对 C 或其他 Arm 具有统计显著优势。C 的 answerability 低于 B，也说明“更复杂检索”不必然
改善拒答校准。

#### 有界结构修复与成本

50 个去重 Generator 调用由 5 个共享 plan、15 个 A direct、15 个 B synthesis 和 15 个 C
synthesis 组成：25/50 一次通过，24/50 在第 2 次通过，1/50 在第 3 次通过，无调用耗尽 4 次上限。
A 仅 2/15 一次通过；B 与 C 的 synthesis 均为 9/15 一次通过、6/15 第 2 次通过；5 个共享 plan
全部一次通过。因此“60/60 cell 成功”不能被解释成“一次结构输出稳定率 100%”。

D 共审核 76 条 C 主张，产生 532 个逻辑 Judge 样本，其中 528 个有效；因结构修复实际发生
573 次请求。最终判定包括 fully_supported 37、partially_supported 15、not_supported 22、
refuted 1、unknown 1；47/76 条通过门控，7 条升级人工复核。平均投票一致率为 0.934，最低
0.4286。Generator 与 Judge 的累计 token 仅用于描述成本，不用于质量计分：

| 调用层 | prompt | completion | reasoning | cached |
|---|---:|---:|---:|---:|
| Generator（50 个去重调用） | 291,782 | 284,376 | 224,047 | 75,520 |
| Judge（573 次实际请求） | 1,007,447 | 1,134,344 | 1,060,638 | 773,696 |

v4 保存初始提示、最终成功提示、Schema、响应和结构化输出哈希及 `attempt_count`，但不保存原始
provider 响应、私有推理或逐次 repair 文本。因此离线审计可验证最终输出、次数上限与哈希链，
不能重构每一次 repair 对话；这是 `production_ready` 仍需附带的明确边界。

## 4. 仍未完成的比赛要求

- 基于同一冻结输出的完整 D1–D9 自动评分，以及与输出级专家九维分数的比较；现有参考没有
  这类总分，不能补造 Spearman、MAE 或 ICC；
- 正式“好—中—差”三档受控输出、完整 12 类攻击集与干净样本误报率；
- 扩展题集、量表冻结、2 分钟 Demo/GIF 和开源许可证。

当前结论是：评估工程和真实 Hy3 Pilot 已运行，术语正误判别较强但受长度偏差影响；Claim
四分类门禁表现不足；正式 A/B/C/D v4 已完整运行，D 的 answerability 点估计最高但未达到统计
显著。后续结果必须继续保留失败样本和分母，不能因为指标不理想而更换专家参考或删除运行。
