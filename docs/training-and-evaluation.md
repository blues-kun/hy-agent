# 面向 Hy3 的训练、专家反馈与评测

本页说明项目训练路线与公开实现的对应关系。Hy3 是应用编排主模型；本仓库实际微调基座为 **Qwen3-4B-Instruct-2507**，核验与工具策略使用独立适配器。

## 1. 知识库初轮适配与医学专家反馈

按项目负责人补充的过程：先结合知识库进行初轮模型适配，将该阶段的回答和证据说明通过邮件发送给 **5 位医学工作者**征求意见；回收的专业修订经过整理，进入后续 SFT。工具分支另外学习可执行示范，再围绕调用、停止与结果偏好开展强化学习。

邮件材料围绕“问题—模型回答—证据—实验条件”组织，专家反馈重点包括证据支持、条件是否适用、因果表述、错误解释与必要改写。本次不公开邮件地址、通信原件或个人身份，也不把征询对象数量当成逐条审核人数。

### 初轮自监督与自训练的目标

如果使用筛选后的文献原文进行自监督继续预训练（CPT），目标来自文本自身：

```math
\mathcal{L}_{\mathrm{CPT}}
=-\frac{1}{N_{\mathrm{token}}}\sum_{x\in D_{\mathrm{KB}}}\sum_t
\log p_\theta(x_t\mid x_{\lt t}).
```

如果使用模型根据知识库生成的回答、关系或证据核验初稿作为目标，则属于自训练／伪标签学习，而不是原文 CPT：

```math
\mathcal{L}_{\mathrm{self\text{-}train}}
=-\frac{1}{N_{\mathrm{target}}}\sum_{(x,\tilde y)}\sum_t
\log p_\theta(\tilde y_t\mid x,\tilde y_{\lt t}).
```

两者必须按实际输入和标签来源命名。以上是初轮知识适配的目标定义；公开训练包提供的是后续核验 SFT、工具 SFT 和策略 RL，不能用其中的 SFT 日志代替未随包提供的 CPT 训练记录。

### 专家意见怎样进入数据

| 环节 | 整理方式 |
| --- | --- |
| 对齐材料 | 将回复对应到原问题、模型初稿、证据版本与实验条件 |
| 提取修订 | 整理支持关系、条件缺口、错误类型、判定理由及可接受改写 |
| 检查一致性 | 核对修订依据与最终训练输入一致，冲突或不完整意见不自动变成确定标签 |
| 分区与训练 | 同题主张及衍生改写保持成组；按训练／开发分区生成 SFT 记录 |

已公开的**旧专家主张核验集**为 **443 条训练主张 / 43 道题**和 **51 条开发主张 / 5 道题**，并非当前工具训练的总表。每条输入包括问题、专家整理的证据摘要、实验条件与待核验主张；输出契约为 `labels`、`rationale`、`corrected_text`，见[完整字段](../mito/data/FORMAT_CONTRACT.json)。

这些公开记录沿用原有的 `model_assisted` 初稿来源及 `single_user_attested_nonblind` 审核来源记录，没有逐专家意见列；不能据本轮邮件流程说明，将其重标为五人独立盲审或计算五人一致性。标注样例中的记录也不与当前数据直接相加为独立样本总量。数据字节及来源字段保持不变。

## 2. 小模型与训练配置

| 项目 | 核验 SFT | 工具 SFT |
| --- | --- | --- |
| 基座 | Qwen3-4B-Instruct-2507 | Qwen3-4B-Instruct-2507 |
| 训练参数 | BF16 LoRA，r=16、α=32、dropout=0.05，all-linear | BF16 LoRA，r=16、α=32、dropout=0.05，all-linear |
| 学习率默认值 | 1e-4 | 2e-5 |
| 单卡 batch / 梯度累积 | 1 / 4 | 1 / 8 |
| 默认训练量 | 2 epochs | 100 steps |
| 最大上下文 | 8,192 tokens | 8,192 tokens |
| 监督范围 | assistant completion | 当前 assistant 动作 JSON 与 EOS，不监督历史动作 |

这是代码默认值，不是约 100 步 RP-GRPO 阶段表的运行证明；命令行参数可覆盖默认值。运行时保存实际配置、代码版本、数据和适配器哈希。

SFT 使用掩码后的 token 交叉熵：

```math
\mathcal{L}_{\mathrm{SFT}}
=-\frac{1}{\sum_t m_t}\sum_t m_t\log\pi_\theta(y_t\mid x,y_{\lt t}).
```

LoRA 冻结原权重，以低秩增量更新目标层：

```math
W=W_0+\frac{\alpha}{r}BA.
```

系统、问题、证据和工具观察不进入 SFT 目标损失。工具示范来自实际执行并经独立回放的规则轨迹，代码标记为 `executed_rule_demonstration`，不是五位医学工作者亲自演示的轨迹。

本轮实际工具策略链路为 **Qwen3-4B → 旧工具 SFT → 本轮 SFT100 → 四组 RL（B1 / B2 / LOO / B3）**。旧工具 SFT 留有 **234 条轨迹、936 次助手动作**的历史审计记录；本轮 SFT100 使用上述 **911 条训练动作**。SFT400 是另设的训练时长对照，当前 RL 仍从 SFT100 初始化，不把两者串成同一条训练链。

正式 RL 从通过准入的工具 SFT 适配器继续，只更新 policy LoRA，并冻结同一个初始 SFT 适配器作为 KL 参考。核验适配器不直接充当工具策略起点。

## 3. GRPO / RP-GRPO 与偏好反馈

RP-GRPO 对同一目标建立有意义的环境条件差异，以真实返回让模型区分“能完成”与“当前材料不足”。每侧采样 G 条轨迹，共 2G 条；领域任务偏好通过任务要求、证据约束、停止规则、工具代价和配对效用表达。

普通 GRPO 的组内标准差使用 population 定义；RP-GRPO 则采用配对效用、同侧 leave-one-out 基线与固定尺度优势。`η=0` 的 LOO 对照用于区分优势估计变化与配对目标本身的作用。

完整公式、系数 2、更新目标与代码对应见 [RP_METHOD.md](../mito/rp_grpo/RP_METHOD.md)和[算法实现](../mito/rp_grpo/algorithms.py)。当前实现不训练独立奖励模型或价值网络；PPO 式裁剪不是一套已完成的 PPO baseline，未提供 PPO 数值结果。

代码默认每侧 `G=4`、`η=0.5`、裁剪系数 `ε=0.2`、KL 系数 `β=0.04`、学习率 `1e-6`。每条轨迹先对助手动作 token 取均值，再对轨迹取均值；`exp(d)-d-1` 为采样 KL 近似。16 个配对效用值只来自 8 条真实轨迹，不能当作 16 个独立样本。

工具调用覆盖：

| 动作 | 真实作用 |
| --- | --- |
| `list_documents` / `search_evidence` | 盘点授权材料、查询候选 |
| `read_passage` / `read_statement` | 获取原文与位置、内容哈希 |
| `query_metrics` | 对冻结测量快照执行限定统计 |
| `finalize` / `stop` | 提交有依据的结果，或在已检查范围内恰当停止 |

成功与奖励由环境核对真实读取、数值重算、授权范围及引用绑定；非法调用和固定工具成本代理参与扣分。模型自述“成功”不能替代环境评分，成本代理不等于云服务账单。

## 4. 评测与归因

### 核验模型

使用相同问题与证据，比较基座和专家 SFT。报告 JSON 与标签契约合法性、支持关系各类 F1、Macro-F1、错误支持和过度保留判断；开发集缺少 mixed 类，应同时注明观察类别与固定四类别口径。非法或缺失输出不丢弃，按问题组而非独立 JSON 行进行重采样比较。

### 工具策略

先检查无规则 SFT 的实际执行与回放，再进行 RL。B0 为 SFT 加固定规则，B1 为独立任务 GRPO，B2 为相同配对日程 GRPO，LOO 为 η=0，B3 为 RP-GRPO。保持模型起点、合法任务池、工具、奖励与预算一致；B2、LOO、B3 使用相同配对日程。

主指标是端到端成功、配对双侧成功、错误支持／无效测量，辅以文本与数值分项、参数合法性、反馈恢复、过早停止及实际工具次数、token 与耗时。失败保留在分母，日志由独立回放核验。

按每步 8 条真实轨迹计，RL 到 200 步时名义上每组生成 1,600 条轨迹，到 400 步为 3,200 条。这些是对现有任务池的重复探索量，不是新增独立任务或专家标注量；实际完成量仍以运行日志为准。

### Hy3 应用验证

接入后计划在同一任务集比较 Hy3＋知识库、Hy3 自检、固定规则与领域小模型工具，检查专业错误是否减少、任务是否完成，以及整条链路的延迟和成本。训练环境里的策略收益与 Hy3 工作台整体收益分别报告，不将现有 GIF 当成这些消融实验的成绩。

目前公开可用评测分区为开发集，独立来源／实验族验证、不同种子重复及正式 Hy3 接入比较后续补齐。代码默认三种子列表不是已完成三种子实验的证明；[约 100 步阶段汇总](stage-results.md)仍按项目给定数值记录，不反推缺失的运行参数。
